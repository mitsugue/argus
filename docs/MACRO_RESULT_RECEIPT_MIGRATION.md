# 指標結果の取得時点の移行

既存BLS（NFP/CPI/PPI/JOLTS）・FRED（PCE/GDP/FOMC）系列は公表時刻を直接検証していない。新しい成功結果は全応答の読取後に `receivedAt` と `availableFrom` を記録し、`releasedAt` は null、`availabilityBasis=RESPONSE_RECEIPT`、`historicalVintageVerified=false` とする。CPIの既存 `macro-cpi-result-v2` は維持し、それ以外の新規成功結果を `macro-series-receipt-v2` と識別する。

`sourceResponseSha256` は取得した解析済みJSONの正規化SHA256であり、HTTP原文そのもののhashでも歴史的ビンテージの証明でもない。複数系列は名前付き辞書（PCE: headline/core、FOMC: upper/lower）全体を照合する。値の計算・対象月の選択・予定イベント時刻・取得頻度・予算は変更しない。非CPIの既存「取得済みなら追加取得しない」条件も維持する。

旧保存結果・改訂・説明の本文、ID、hashを一括書換えしない。旧結果の releasedAt には取得時計が使われていたため、画面向け要約と説明入力だけで公表時刻を未確認へ投影する。明示された妥当な receivedAt がなければ `LEGACY_UNVERIFIED` とし、旧 releasedAt や updatedAt から取得時刻を補わない。原本は既存改訂台帳に保持される。新規取得が既存経路で発生した後だけ新仕様の結果が追加される。旧原本の削除条件は設けない。

同じ数値の再取得は経済的な新改訂として重複登録せず、最初の保存snapshotを保持する。時点仕様のschemaが変わる初回は新しい結果IDとなり、旧説明を履歴へ保持して再照合待ちにする。旧コードへ単純に戻すと取得時刻を公表時刻と呼ぶ表示が戻り得るので、この時点区別を維持する修正版を用いる。復旧時も履歴を削除・再hashしない。

空応答/失敗/未実装に結果の availableFrom を付けて成功へ変換しない。新規成功の時刻が不正なら取得エラーとして停止する。

この変更は指標値と予定イベントとの対応確認、歴史的公表ビンテージ、日本株の1/3/5営業日の材料反応接続、予測力、実データ受入の完成ではない。比較側へ未確認時刻を流し込まない。指数PERの403も解決していない。版は段階候補v13.7.51のまま、正規登録・最終検査・版識別更新・本番配信は別途正規手順に従う。
