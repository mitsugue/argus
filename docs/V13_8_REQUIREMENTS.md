## 0. 現行仕様と旧資料の関係

本書を13.8の製品方針の入口とする。同じ事項ではオーナーの最新の直接指示を
優先し、本書、13.7機能整理、分析エンジン共通要件の順に読む。
13.5〜13.7の旧版順序を13.8の着手条件にしない。受入台帳は検証状態の記録であり、
古い「未着手」をそのまま再開発の指示とせず、実装・証跡に照合する。
本文の日時付き状態はその時点の記録で、現時点の本番状態を保証しない。
共用の認証・保存・復旧・配信検査は継続し、退役機能を復活させない。

画面は結論とその意味、重要な数字、詳しい根拠の順に置く。統合AIの結論を
下の各ブロックで繰り返さず、各ブロックは結論を確かめる固有の根拠を示す。
同じデータは対象・計算方法・利用時点が一致する場合に共通化する。
「期間が長い・新しい」だけで異なる定義の系列へ置き換えない。

### 日経チャートへの研究結果の接続（2026-10-05）

実装対象：日経平均の過去約6か月と未来約3か月を同じ日付軸に表示する。初期表示は日経終値・PER15〜21倍・参考予測。各層の常時表示と操作は§9の最新指示に従う。従来の過去比較は切り替えで残し、水準の地図・FUTURE MAP・候補の詳細表示も残す。

- PER線は各日の前営業日の製品用推計EPSを使う。欠測を現在値で埋めない。右端は保存した朝の地図と同じ推計値で、古ければ対象日を表示する。
- 外部の見立ては既存のFUTURE MAPの期間と水準の中点。幅は帯、点は白い点線で接続する。未検証と表示し、ARGUSの予測経路とは扱わない。
- 候補は未決着で目標・崩れが決まった記録だけ。20営業日の期限は既存の取引日規則で補い、PER連動の目標は朝の水準に更新して毎朝変動と明記する。元の事前記録は変更しない。
- 山・谷は終値4%反転で確定した点と未確定点を区別。確定条件の価格を整数に丸めて条件を変えない。
- 次のPER線への頻度と日数は、水準の地図と同じ距離の表から表示する。PER線で反発する頻度とは区別する。
- 描画配列は既存の比較応答の `levelMap.chart` に同梱する。外部取得・AI生成・保存処理は増やさず、描画データの作成失敗は `chartError` として分離する。

検証箇所：`test_jp_market_chart_layers.py`、`web/scripts/research-chart.test.cjs`。実装・手元検証と、本番受入の完了は別に記録する。

### 終値更新の回復と表示の独立（2026-10-07）

15:31・15:35・15:45に確定終値を確認し、16:05にも不足した価格を再確認する。
当日の推計入力は16:35から別に確認する。J-Quantsのバリュエーション指標の
[公式更新目安](https://jpx-jquants.com/ja/spec/data-update)は16:30頃であり、更新完了の保証ではない。
夜間の再起動・日付変更・休場日でも、直近の終了した日本株営業日の終値または推計入力が
不足していれば毎時1回まで回復を試す。両方がそろえば追加取得しない。重い処理の同時実行制限は維持する。
受信時刻は日本時間・UTCの文字列順ではなく同じ時刻へ変換して判定する。

過去比較が準備中でも、取得済みの新しい終値・PER描画を応答と画面へ渡す。
端末の保存済み比較で新しい描画を上書きしない。過去比較の失敗と描画の失敗は別表示とする。
引け直後と引け後の終値・PER入力待ちの間は、表示中の画面が保存済み応答を1分間隔で読み、
通常は10分間隔へ戻す。これは外部取得やAI生成を起動しない読み取りで、背景からの復帰時に一斉取得しない。
朝の事前記録・予測・採点は変更しない。実際の受信と所有者の端末表示は配信検査と別に確認する。

価格の目盛りでは、見出し・上下のPER価格・終値との差・距離に応じた過去の到達割合・
展開した計算表を同じ表示用終値・EPS・ATRにそろえる。終値は先に更新し、EPS待ちの間は
EPSの対象日を表示する。新しいEPSが届いたら価格と距離を再計算する。朝の固定値は
「朝の固定記録を見る」に分け、答え合わせと候補の事前目標を変えない。
過去の到達割合は新しい距離帯から選び直すが、将来の予測確率へ置き換えない。
同じ距離帯なら割合が変わらない場合がある。未受信の当日終値は取得待ちと表示し、
前日値を当日値として示さない。上下の整数PER価格はEPS×倍率で表示し、近い転換点と
まとめた詳細表の価格で置き換えない。割合は同じ価格・距離に対応する値だけを使う。表示中の定期読取は15:30の境界で1分間隔へ切り替える。

## 1. オーナーの基本指示(2026-10-03)

> 統合AIがまず中央(一番上)にいる。その下に各機能(ニュース、イベント、日経、七つの警戒条件など)がある。統合AIはそれらを読み込むが、数字だけを見るのではない。今、人間の投資家が今の市場をどういうところにいると見ているのかをきちんと把握する。つまり**現在位置の解釈を間違えない**。そのうえで各データを読み解き、トップで発表する。ほかの箇所も表現を統一する。

> 統合AIは、投資家が現在をどう見ているか、どうなると怖いと思っているか、どうなるといいと思っているか、どうなると下落が始まると思っているか、という不安や予測を理解したうえで、各機能が上げてきたデータを読み解く。例:今週末にトランプ大統領がイランを攻めるかもしれない、そうなると昨夜の熱狂は一気に冷めるかもしれない。米国が軍を数千人追加派遣している。こうしたことはデータではなく、まずニュースにある。それを蓄積し、過去の動向を記憶しながら情報を磨き、それぞれのニュースが複雑に更新されていかないといけない。

> 今回の失敗は、必要なデータがなかった・遅かった・古かったことが原因。それは直す。ただしそれは統合AIの下部組織(各機能)の充実の話であり、統合AI自体の理解とは別に必要。

**この指示は13.8の最優先事項であり、本書の全項目を完了まで実施する(オーナー 2026-10-03)。**

## 2. きっかけになった失敗(2026-10-02 夜の米雇用統計)

| 何が起きたか | ARGUSの表示 | 問題 |
|---|---|---|
| 米国は年内の追加利上げを示唆していた。雇用統計は弱く(+29千人・失業率4.2%)、市場は「追加利上げはない」と読んだ。FF金利先物の示す政策金利の予想は約2bp下がり、引けまで戻らなかった。株高(SOX +2.4%)、VIX −6.6%、日経先物(CME)は終値比+2.2%(一時70,205) | 「材料は逆風寄り」「金利を軸に日経を慎重に見ています」、発表後「米10年+10bp・VIX −2.1%」 | 現在位置(追加利上げ観測)を持たず、市場の読み(利上げ回避の安心)を導けなかった |

原因(コードと本番データで確認済み):
1. 発表後分析のGPTに渡っていたのは、その時点の米10年・ドル円・VIXの水準と、公式結果・事前シナリオだけ。市場反応の数字、利上げ観測、FOMCの示唆、関連ニュースは渡っていなかった。
2. 反応の基準値が「発表直前」ではなく「発表後の初回観測」で、取得元も混在していた。
3. FF金利先物(政策金利の予想)と夜間の日経先物を取得していなかった(後者は13.8.17で対応)。
4. Todayの「米10年金利の上昇=逆風」には根拠がなかった(2012年以降、+15bp以上の5日後も日経上昇61%、普段57%)。
5. 統合AI(市況ブリーフ)は、出来事の記憶も前回の結論文も読んでいない。入力されるニュースは、メールの重要2件と市場ショックだけ。

### 3-1. 市場の現在位置メモ(新設、ただし既存の記憶の上に作る)

投資家がいま見ている主要テーマを5〜8個持つ。初期の候補: 米国の追加利上げ、AI・半導体相場、中東(イラン)情勢、日銀、円相場、日本の財政、国内需給。

テーマごとの欄:

| 欄 | 内容 |
|---|---|
| 今の市場の見方 | 多数派の読み。根拠(ニュースID・市場データ)つき |
| 期待のシナリオ | こうなると上がる |
| 警戒のシナリオ | こうなると怖い・下落が始まる引き金 |
| 市場の織り込み | 測れるものは数字で(例: FF金利先物から見た利上げ予想) |
| 次に確かめる予定 | FOMC・雇用統計・CPI・日銀会合など |
| 更新履歴 | 日付・出典・何が変わったか(例: 米軍の追加派遣で緊張の段階が上がった) |
| 状態 | 強まった/弱まった/変わらず/終わった |

再利用するもの(並立させない):
- 出来事・仮説・検証・反証の記録: `argus_causal_event_memory.py`(追記専用・ハッシュ鎖)。テーマは既存の family を土台に拡張する。
- 版の保存と前回比較: 市況ブリーフの履歴(`argus_analysis_history.py`、遠隔バックアップあり)。
- 前回の結論を次に渡す実装例: 統合説明(`argus_owner_dialogue_api.py` の previousView)。

第1段階(2026-10-03 実装・テスト済み、本番未確認): `argus_market_position_memory.py`。7テーマ(米国の利上げ・利下げ観測/AI・半導体/中東・イラン/米長期金利・財政/日銀/円/関税)。重要ニュース(HIGH以上)・測った発表反応と読み・発表前の織り込み(FF先物)・次の予定を追記専用で蓄積し、永続ディスクに保存。市況ブリーフの根拠(source=market_position、P1)として統合AIに渡し、「まず現在位置を把握してから他の根拠を読む」と指示。応答に `marketPosition` を同梱。
第2段階(未着手): 統合AIがテーマごとの「期待・警戒・引き金」を書き、検証して記憶へ戻す。画面に「市場の現在位置」の欄を出す。

更新のしかた:
- 重要ニュース(HIGH以上)やイベント結果が入ったとき、関係するテーマだけを書き足す。ゼロから作り直さない。
- 当時の版は保持し、結果を見て過去の記述を書き換えない。
- 根拠のない数字は書かない(既存の検証 `validate_unified_ai` と同じ規則)。

### 3-2. 統合AIの読み方

1. まず現在位置メモを読む(どのテーマが今の主役か、何が警戒されているか)。
2. 各機能のデータを、その文脈で読み解く。例: 「追加利上げが警戒される中で雇用が弱く、FF金利先物は利上げ予想を下げたまま引け、株高・VIX低下 → 市場は『利上げ回避の安心』と読んだ」。同じ弱い雇用でも、株安・VIX上昇なら「景気悪化の不安」と読む。
3. トップで発表する: 結論、期待と警戒のシナリオ、見方を変える条件、次に確かめる予定。
4. 前回の結論文を受け取り、何が変わったかを明示する。

### 3-3. 表現の統一

- Today・イベント欄・ニュース欄・統合説明は、同じテーマ名と同じ読みを使う。欄ごとに違う見立てを言わない。
- イベント欄は「結論/過去の成績/見方を変える条件」の3行を基本形とし、細かい数字は折りたたむ。
- 材料は「何が起き、株価の何に影響し、次に何を確認するか」を短く伝える。「方向を決められない」だけで終えない。成績がない影響を確率や断定へ変換しない。

## 5. 当たり外れの確かめ方

- 新しい予測や材料は、作る前に過去データで当たるかを測る。結果は画面に併記する(例: 13.8.17 の夜間先物の成績表)。
- 統合AIの「読み」(例: 利上げ回避の安心型)は保存し、その後の市場の動きと照らす。読みの型ごとに成績を集計する。
- 現在位置メモのテーマごとの「こうなったらこう動く」も保存して照合する。
- 未検証の頻度を確率として表示しない。

- SQは清算に向けた売買が重なり、大きく上下に振れる可能性まで説明する。「方向を決められない」だけで終えない。
- 重大ニュースはトップの４枚目に元の見出し・理由・確認状態を表示し、詳細へつなぐ。
- PER表の冒頭に「この表は、企業の利益に対して、日経平均が何倍の値段になっているかを示す目盛りです」と書く。倍率と価格の例は毎朝の保存値に合わせる。
- 研究チャートは直近を拡大でき、外部の見立ての各点について期間・価格・前日終値との差を確認できるようにする。各層は常時表示し、重なりは拡大と配置で読みやすくする。

### 価格の目盛り・チャート・ニュースの見せ方（2026-10-05）

- PERは「日経平均の価格の目盛り」として、前日終値・倍率と、直近の整数倍率の価格・距離を先に表示する。全価格表と研究の答え合わせは各専用の詳細に残す。統合AI全体の根拠は見通し側に置く。
- 研究チャートの各層は常時表示する。白い点線はFUTURE MAPの「参考予測（未検証）」で、期間の中央の点を特定日の到達予想とは表示しない。期間中の点は中央の日を過ぎても保持する。青線の最終終値の日付と、今日の現在値を含まない状態を明示する。
- チャートの直下に拡大・縮小・左右移動・今日へ戻る操作を置く。ドラッグ・2本指の拡大縮小は元の価格・日付を変えず、描画範囲だけを動かす。次のPER線へ届いた過去の頻度と日数は大きく表示する。
- データ不足の実際の理由を閉じたカードにも表示する。7条件の成立数と判断への有効性の検証状態は区別する。
- ニュースは記事の受信時刻、一覧を読んだ時刻、取り込みの稼働状態を混同しない。既存AIが読んだのは見出し・抜粋であり、全文確認と表示しない。記事への影響説明、方向、市場反応確認は別の事実として保持し、一般的な波及経路を個別記事の解析に置き換えない。
