## 需給変化

`jp_market_dynamics` は既存の公表時刻・訂正管理を使い、同一対象・系列・単位・対象週の
買残と売残を結合する。片側が欠けた週へ前週値を転用しない。倍率差を順序に依存しない
対称分解で示す。Bは買残、Sは売残、0/1は前後の観測である。

- 買残側寄与 = (B1 − B0) × (1/S0 + 1/S1) / 2
- 売残側寄与 = (B0 + B1) × (1/S1 − 1/S0) / 2

両者の和は倍率差に一致する。丸めは表示時に行う。売残ゼロ・不正値・対象や単位違いは
不明とする。買残ゼロは有限倍率として扱い、そのゼロを分母とする変化率は不明とする。
間隔が7日以外の変化を「前週差」と表示しない。売残減少を買い戻し注文の直接観測とは呼ばない。
評価損益率の正負規約と百分率/小数を明記し、損失を正値へ揃える処理を別に持つ。
実データ提供元の定義・接続・有効性は別途必要である。

## 過去局面選択

`jp_market_analogs` は日経平均そのものの価格窓と、締切までに公表された状態、条件順序、
材料後の観測済み反応をスナップショットに固定する。選択関数には未来経路を渡さない。
訂正の初出時刻、対象、単位、営業日窓を検査し、後日入手したデータが真正な過去版だったとは
宣言しない。履歴の公表時刻仮定と、改訂前スナップショットの証明は別である。

研究用の初期仕様は20営業日、最大3候補、候補間20営業日、最大距離0.75。
価格の基準値100からの差は5ポイントを尺度とする。状態量はコードの明示した物理単位の
尺度で比較する。条件は同日発生を同時点として扱い、順序を編集距離で比較する。
材料反応は同種イベントかつ同じ観測営業日数同士を比較する。
警戒条件と回復条件を単純な点灯数の強気度へ合算する処理ではない。

これらは独立検証前の仕様であり、予測有効性が確認された閾値ではない。調整する場合は
ポリシーIDを変え、評価に使った期間を未使用の独立期間として再利用しない。
欠けた状態・順序・反応は明示し、部分比較を完全な市場類似へ昇格しない。
特徴が古い場合も比較から外す。選択後に初めて、当時のその後の参考実績を結合する。
選択の入力と出力IDを保存し、将来実績を変えても選択は変化しないことを検査する。

## 形状と円換算・現在予測

`jp_market_price_paths` は形状の基準100と円換算を分ける。円換算には同じ基準日・指数の
指数ベースPERと指数終値を用い、指数EPS = 終値/PER として定義を揃える。
時価総額加重PER、ETFや個別株EPSの代理入力は受け付けない。短期のEPS一定を仮定と
明示し、過去の形状変化を過去の実測PER変化とは呼ばない。固定PER帯への切詰めはしない。

選択された完全な参考経路が2件以上あれば、各営業日の中央値と25–75百分位帯を計算できる。
これは未検証の条件付き研究予測であり、帯の将来包含率は主張しない。選択時点より後に
判明した経路を使わない。1/5/10/20営業日という対象期間と上昇・横ばい・下落の分類境界を
出力に含める。初期の横ばい境界は±0.5%。これは的中確率ではなく参考事例の頻度を数える
ための固定研究仕様である。件数、分母、出現頻度、予測確率、判断の確度は別項目とし、
未検証の予測確率と判断の確度はnullのままにする。

### Device envelope encoding preparation

The existing AES-GCM envelope v1 now base64-encodes ciphertext in 32 KiB chunks,
avoiding a single function argument list that fails for full device histories.
A multilingual payload exceeding 1 MB round-trips through the actual encrypt /
decrypt functions with exact data equality and no local-store writes; an
incorrect passphrase still fails authentication. This is local tested code only,
not authenticated cloud upload, restart restore, cross-device sync, or iPhone
acceptance. Existing relay size/auth/persistence integration remains outstanding.

### Backend delivery preparation

Japan analysis modules and the official SQ calendar are explicit backend deploy
inputs in both the Render blueprint and the release classifier. A calendar-only
update must reach the running backend; documentation/test-only changes preserve
the current backend. The 31 deploy-scope/guard tests pass locally. The live
Render service is dashboard-managed: its corresponding path filter still needs
to be verified and updated before the integrated 13.6 release. This preparation
is not evidence that the new analysis is running in production.

### Usage store first-write concurrency

Initialization now publishes a complete SQLite database atomically without
replacing an existing destination. Eight concurrent first callers each retain
their own receipt. A failed publication leaves no empty database that could be
misreported as an empty history; retry can initialize safely. The usage receipt
and durable store tests total 26 passes. Runtime integration is still pending.
