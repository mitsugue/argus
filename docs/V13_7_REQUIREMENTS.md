## 費用削減の順序

1. 同一データ・記事・イベントの重複取得、重複AI処理、描画時の不要な呼出し、複数スケジューラーの二重実行を減らす。
2. 取得・決定的な差分/計算・説明を分離する。重要入力、保有情報、ルール版、判断条件が同じなら説明を再利用し、古い生成日時を新しい評価日時へ書き換えない。
3. 情報源の更新頻度、市場時間、イベント時刻へ合わせる。休場中も重大ニュース監視は維持し、無限再試行や高額な代替連鎖を防ぐ。
4. 定型処理と複雑な分析を分け、モデル変更は代表例で欠落と説明品質を確認する。既存の予算機構を活用する際は低優先の生成から抑制し、上限停止を正常動作と表示しない。平易な説明は削らない。
5. 実際の契約重複や未使用サービスは依存・復旧経路・移行費・保守負担を確認して整理する。監視・認証・バックアップ・判断記録は一括削除しない。使用量削減と契約請求額削減を区別する。

ChatGPTの契約をAPIやARGUS自動連携込みと仮定しない。日次整理・深掘り、速報検知、保有/判定への接続、履歴/検証を分けて代替可否を検討する。見落とし・遅延・有用性・人手・総費用で比較し、高額な二重運転は常設しない。
