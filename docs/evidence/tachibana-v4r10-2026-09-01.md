# Tachibana e-Branch v4r10 engineering evidence

Retrieved: 2026-09-01 JST. Sources are primary Tachibana materials unless a
row is explicitly labeled third-party precedent.

## Current contract

- Current API: v4r10, released 2026-08-29. Production root is
  `https://kabuka.e-shiten.jp/e_api_v4r10/`; v4r9 is scheduled to retire on
  2026-09-27.
- Authentication: HTTP POST JSON to the current `/auth/` endpoint using
  `CLMAuthLoginRequest`, `sAuthId`, increasing `p_no`, current JST
  `p_sd_date`, and `sJsonOfmt=5`.
- The credential guide's `.der` artifact is Base64 text whose decoded payload
  is an unencrypted PKCS#8 DER RSA private key. The Linux client consumes the
  equivalent unencrypted PKCS#8 PEM form. Local conversion must validate RSA
  structure and size first, write mode 0600 through a same-directory temporary
  file, fsync, and atomically replace; no key bytes or fingerprints are logged.
- A successful response carries encrypted REQUEST, MASTER, PRICE, EVENT, and
  EVENT-WebSocket virtual URLs. The current Python sample Base64-decodes and
  decrypts each using RSA-OAEP with SHA-256/MGF1-SHA-256 and the client-side
  PEM key. The URLs are one-session credentials, opaque, format-unstable, and
  invalidated together. A new login invalidates the prior set.
- REQUEST/MASTER/PRICE are one-question/one-answer; parallel requests are not
  guaranteed. EVENT permits one long-lived connection and is best-effort,
  thinned market data rather than a complete tick feed. A later connection
  replaces the earlier one.
- The REQUEST common envelope requires `p_no` on every response and requires
  it to echo the corresponding request value. ARGUS rejects a missing or
  mismatched echo and expires the session so a delayed same-function response
  cannot be accepted as current.
- Logout is `CLMAuthLogoutRequest` on the REQUEST virtual URL. The client must
  then erase every virtual URL reference.
- The HTTP transport installs a permanent dependency-log filter for both complete
  virtual URLs and urllib3's path-only DEBUG form; opaque virtual path tokens are
  credential-equivalent and are never permitted to reach log handlers.
- Current read operations used or allowlisted by this phase:
  `CLMMfdsGetMarketPrice`, `CLMMfdsGetMarketPriceHistory`,
  `CLMMfdsGetIssueDetail`, `CLMMfdsGetSyoukinZan`,
  `CLMMfdsGetShinyouZan`, `CLMMfdsGetHibuInfo`, and
  `CLMStkGetIssueMstKabu`. The live sensor also uses the current official
  MASTER inquiry `CLMStkGetDateZyouhou`; response `CLMDateZyouhou`, day key
  `001`, field `sTheDay` is the provider-calendar source.
- Production compatibility note (observed 2026-09-02): although the current
  v4r10 reference documents Date Information response `CLMDateZyouhou`, the
  live production endpoint returned `CLMStkGetDateZyouhou`, echoing the request
  identifier, with HTTP 200 after successful authentication. ARGUS accepts
  exactly these two public identifiers for Date Information and reports
  `DOCUMENTED` or `PRODUCTION_ECHO_COMPAT`. This exception does not apply to
  PRICE, other MASTER operations, authentication, or any generic validator.
- Production compatibility note (observed 2026-09-03, 10:46 JST, one bounded
  names-only diagnostic session after the 08:27 JST live acceptance stopped at
  `PROVIDER_DATE_SCHEMA` / `TOP_LEVEL_FIELD_UNKNOWN`): the same echo response
  names its row list `aCLMStkDateZyouhou` instead of the documented
  `aCLMDateZyouhou`. ARGUS accepts that list key only together with the echoed
  `sCLMID`, normalizes it to the documented key before any consumer reads it,
  and reports `responseListMode` as `DOCUMENTED` or `PRODUCTION_ECHO_COMPAT`.
  Both keys at once, or the echo key under the documented `sCLMID`, fail closed
  as `RESPONSE_LIST_SHAPE_INVALID`. The safe read diagnostic now also carries
  `unexpectedTopLevelFields` (names only; identifier characters, at most 8).
- v4r10 removed the generic bulk master/news operations including
  `CLMEventDownload`, `CLMMfdsGetMasterData`, `CLMMfdsGetNewsHead`, and
  `CLMMfdsGetNewsBody`. They are not implemented.
- `CLMMfdsGetMarketPrice` accepts at most 120 symbols, but ARGUS Phase 1 caps
  the configured set at 64 and defaults to 32. The published 10 requests/sec
  control is a ceiling, not a capacity target; ARGUS defaults to 30/minute,
  one in flight, at most two read attempts, and no automatic auth retry. HTTP
  bodies are streamed under endpoint-specific byte caps and an independent
  monotonic total deadline, so an inter-byte slow drip cannot retain that
  serialized request lock indefinitely.
- API URLs close daily with the system; general login is unavailable around
  03:30–05:30 JST. Demo login is documented as 08:30–27:00. Maintenance and
  provider-specific downtime remain possible.
- Fixed-IPv4 restriction is strongly recommended in the credential guide.
  Public material does not establish that it is mandatory.

## Retained EVENT field contract

The current v4r10 reference deliberately links the unchanged v4r7 EVENT/FD
field table. The subscription request selects commands with `p_evt_cmd`; every
response is classified by the distinct `p_cmd` field. Phase 1 accepts only ST,
KP, FD, SS, and US and rejects missing/unknown commands. EC/order, news, and
private commands are not representable.

WebSocket messages are RFC 6455 text frames containing the EVENT application
format directly: SOH (`0x01`) separates fields, STX (`0x02`) separates a field
name and value, and ETX (`0x03`) separates repeated values only where a field is
documented as list-valued. The entire frame is **not** Base64 or gzip encoded.
Only Japanese-text values are documented as Base64 of Shift-JIS: EC `p_IN` and
NS `p_HDL`/`p_TX`; those commands remain forbidden here. FD `xLISS` is the
separate documented Shift-JIS-as-hex case. None of the admitted ST/KP/FD/SS/US
fields is decoded as whole-frame Base64.

`p_no` is the connection-local consecutive notification sequence across all
accepted commands. It is used for gap detection, not row ordering. `p_ENO`
belongs to EC/NS/SS/US where specified and is globally ascending but not
consecutive within one connection. The specification says the underlying data
time is not necessarily chronological; it does **not** permit in-connection
`p_ENO` regression. ARGUS resets both sequence checks on reconnect, while
`p_CT` per SS/US state key prevents an older replay from rolling current state
back. `p_ENO` does not order FD. Equal `p_CT` values with conflicting state for
one key are ambiguous and fail closed until a newer effective state arrives.
An FD frame may contain multiple subscription
rows. The wire keys are row-prefixed (for example `p_1_DPP` and
`t_1_DPP:T`), and the instrument comes from the immutable subscription
row-to-symbol map rather than from an invented symbol field.

`KP` proves only transport liveness. `SS` has no market/account/unit dimension;
ARGUS therefore derives its logical key as provider `p_PV`. Within that key,
`p_LK` is login permission
(`0` maintenance, `1` permitted, `2` outside service, `9` test) and `p_SS` is
the e-Branch system's open/closed state. `p_LK=1,p_SS=1` is therefore not a
provider-health contradiction: the official example itself shows login
permitted with system closed. System closure is neither exchange closure nor
provider unavailability.

`US` describes operations/order-acceptance state. ARGUS derives its logical
identity from the complete official dimension tuple
`p_PV,p_MC,p_GSCD,p_SHSB,p_UC,p_UU`; `p_EDK` and
`p_US` are state values for that identity. Multiple identities legitimately
coexist. ARGUS retains at most 64 latest states, ordered by `p_CT` within each
key, then derives Tokyo cash-equity constraints only from category `01`, unit
`0101`, TSE market `00/01`, empty underlying, and stock/empty product. It never
lets an unrelated category become global state. For cash equities, `100` means
morning acceptance start and `200` means afternoon acceptance start; neither
proves continuous trading. Definite close codes can constrain the calendar,
`EDK=2` halts, and `898/899` degrades, but no US code synthesizes `OPEN`.
`ST` remains terminal and the server disconnects.

The official replay contract resends every undeleted current-business-day SS
and US notification on each connection. Arrival order is retained as EVENT
sequence evidence, but state authority is latest `p_CT` per logical key.
Control effective time, EVENT receive time (`p_date`), and FD market-data time
are never substituted for one another. A state from a different provider
calendar date is retained only as historical replay and cannot control the
current session.

## Provider date, phase, health, and freshness precedence

The live sensor establishes four separate dates/times:

1. provider calendar date: `CLMStkGetDateZyouhou` day key `001` / `sTheDay`;
2. current trading date: ARGUS's versioned official JPX calendar, corroborated
   by the provider calendar date;
3. EVENT/PRICE packet date: `p_date`/`p_rv_date`, required to match the provider
   date and remain within the fixed clock-skew bound;
4. status effective time: SS/US `p_CT`, used only within its logical key.

Wall time supplies the bounded skew check and the existing JPX schedule; it is
not provider-date authority. SS/US `p_CT` never verifies an FD date.

Provider health and market phase are orthogonal. Valid current packets can
prove EVENT/FD data activity while the phase remains `UNKNOWN`. Current
`p_LK=0` is `MAINTENANCE`; current `p_LK=2/9` is `UNAVAILABLE`; `p_LK=1` is
available regardless of `p_SS` open/closed. Current cash-operation faults or
ambiguous equal-time states are `DEGRADED`. Scheduled `PREOPEN`, lunch,
afternoon pre-open, and `CLOSED` are not provider failures.

Market phase comes from verified provider date + verified packet date + the
versioned JPX session. Current SS/US may only constrain that result to
maintenance, halted, closed, degraded, or unknown. A provider CLOSED
constraint during a scheduled OPEN is a conflict and remains `UNKNOWN`.

Market-data freshness uses the current FD/PRICE packet time. Execution
freshness uses `tDPP:T` only after the current trading date and an OPEN phase
are established. Thus a pre-open FD can be `FRESH` board data with no current
execution timestamp, while canonical execution evidence and SDA/cross-
validation promotion remain ineligible. Board comparison may use current
bid/ask facts in PREOPEN or OPEN; execution comparison additionally requires
OPEN, a current-date execution timestamp, and execution progression.

Malformed optional numeric/board fields degrade to unavailable fields and
retain only a bounded safe diagnostic (field token, reason, subscription row,
and public symbol). Raw frames and values are not retained. Identity,
connection sequence, event chronology, packet time, and subscription mapping
remain critical and fail closed.

The table below separates normalized REST-style field names from the actual FD
wire key for subscription row 1:

| Meaning | Normalized/REST code | EVENT FD row-1 wire key |
|---|---|---|
| Current price/time | `pDPP`, `tDPP:T` | `p_1_DPP`, `t_1_DPP:T` |
| Previous close / change / change percent | `pPRP`, `pDYWP`, `pDYRP` | `p_1_PRP`, `p_1_DYWP`, `p_1_DYRP` |
| Open/high/low | `pDOP`, `pDHP`, `pDLP` | `p_1_DOP`, `p_1_DHP`, `p_1_DLP` |
| Volume / traded value / VWAP | `pDV`, `pDJ`, `pVWAP` | `p_1_DV`, `p_1_DJ`, `p_1_VWAP` |
| Best ask/bid | `pQAP`, `pQBP` | `p_1_QAP`, `p_1_QBP` |
| Ask depth | `pGAP1..10`, `pGAV1..10` | `p_1_GAP1..10`, `p_1_GAV1..10` |
| Bid depth | `pGBP1..10`, `pGBV1..10` | `p_1_GBP1..10`, `p_1_GBV1..10` |
| Best ask/bid quote quantity | `pAV`, `pBV` | `p_1_AV`, `p_1_BV` |

The normalizer sorts asks ascending and bids descending, degrades duplicate or
malformed optional levels with bounded safe diagnostics, keeps source time
separate from receive time, and maps missing values to `None`, never zero.
Official current-price time is minute
precision (`HH:MM`); provider receive freshness is therefore tracked separately
and no second-level trade-time precision is claimed.

## Deliberate integration boundary

The receive-only WebSocket lifecycle is disabled by default and is not wired
to the production scanner. The isolated live-sensor candidate now combines
EVENT frame time with ARGUS's versioned JPX calendar, preserving morning and
afternoon pre-open separately from their execution phases. Provider state may
close, halt, degrade, or invalidate that result but cannot make the calendar
open. A time-only `tDPP:T` is not attached to the current date during pre-open,
so a prior-session close cannot be relabeled current. `UNKNOWN` remains
fail-closed. Scanner changes remain outside scope, so no hidden fallback or
automatic authoritative enablement exists.

The provider permits one EVENT connection per customer. Since ARGUS neither
reads nor retains a customer identifier, it conservatively permits only one
EVENT lifecycle per process across all Tachibana sessions. Enforcing the same
constraint across multiple OS processes remains a deployment-orchestration
requirement.

## Information-use risk

The current public conditions broadly say supplied information may not be
accumulated, edited, or processed and must be used within company rules. The
public text does not expressly carve out transient owner-only indicators or
derived-evidence retention. Third-party products demonstrate practical
calculation but do not confer permission on ARGUS.

Until written clarification is obtained, the implementation is disabled,
shadow-only, non-authoritative, raw-data ephemeral, and exposes no persistence
method. Only bounded in-memory state and aggregate derived evidence with
`rawRetained=false` are designed. Production enablement should require owner
sign-off on written Tachibana confirmation covering in-memory normalization,
signals, and derived-evidence retention.

## Industry precedent

- IZANAMI documents Tachibana intraday OHLCV/quote ingestion, derived
  indicators, signals, temporary current-day installation, backtesting, and
  coexistence with J-Quants. Its current public integration still names v4r9,
  so it is precedent, not a v4r10 contract source.
- Trade Stand documents a production Tachibana integration driven by external
  TradingView webhooks. Its execution model is specifically not copied.
- Tachibana's GitHub organization publishes Python public-key login, history,
  snapshot, and EVENT examples. Several older examples print or persist URLs;
  ARGUS intentionally rejects those handling patterns.
- Public Python/Jupyter examples demonstrate quote/depth normalization and
  WebSocket calculations, but use older versions or unsafe URL logging. They
  inform tests only.
