# 13.5〜13.7の残件：定期保存と本番監視の修復

2026-10-05。旧版の段階順を13.8の開始条件にしないことと、旧版の未完了項目を
片付けることは別である。退役済みの機能は戻さず、現在必要な保存・検証を継続する。
全残件の完了宣言ではない。

## A1 予測台帳

従来は、任意のAI実行前の状態確認がHTTPエラーになると、同じジョブ内の正本追記も
実行されなかった。付随する保存処理が失敗した場合も同様だった。

AI処理を最大9分の独立したジョブへ分けた。正本のジョブは、AI処理が失敗・時間切れに
なっても、明示的な実行取消でない限り開始する。別に15分の時間枠を持ち、認証付きで
現在のスナップショットを取得して、既存の形式・実行モード・内容ハッシュ・来歴の検査を
通す。正本の追記とpushを付随処理より先に行う。AIの失敗を成功へ変換しない。

HTTPの途中応答は一時ファイルに置き、成功した応答だけを正本処理へ渡す。
認証に失敗した応答、形式違い、無効な記録を保存しない。
過去に取得できなかった時刻の予測を、今のデータで作り直して過去の実績に加えない。

## A2 本番の動作検査

旧検査では「管理認証なしなら拒否されるか」を調べるリクエストにも管理認証を付けていた。
読み取りの認証と拒否検査を分け、更新・再生成用の拒否検査には認証を送らない。
結果を最後にまとめる方式をやめ、各項目の開始・試行・結果・経過秒を直ちに表示する。

1項目は最大60秒、全体は最大480秒。再試行は最大3回。制限時間を超えた項目と、
残り時間がなく実施できなかった項目は失敗・未確認として残す。
429を認証保護の証明や合格にしない。事前の全エンドポイント二重読み込みは廃止し、
各検査内の再試行に集約する。サーバー応答本文や認証値を新たに出力しない。

## 受入

- 実装：上記の変更済み。既存の判断条件・BUY無効・売買禁止は維持。
- 検査：認証あり読み取り、認証なし拒否、429、入れ子の待機の期限超過、未実施の失敗扱い、
  正本の保存順・内容検査を確認する。
- 本番：変更の配信後に別途確認する。手元の検査合格を本番成功と呼ばない。
- 残件：巡回処理の長時間化、実機、期限付きの検証、データ接続、旧版受入の最終整理は継続。
