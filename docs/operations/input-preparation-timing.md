# 入力準備の実行側の時間記録

既存の入力更新を起動処理が先に実行し、通常収集が同じ処理を待つ場合、
通常収集の `market_inputs` は待機時間だけを示す。従来の収集用の
スレッド内状態では、起動側の工程別時間は記録されなかった。

既存の入力更新の実行側で固定工程ID、開始・終了、経過時間、当該スレッドの
CPU時間を記録し、本人用の既存診断の `marketInputPreparation` へ投影する。
通常収集の終了時と既存の非公開診断保存にも同じ限定項目を渡す。
合流側は記録を開始・更新せず、公開読取は更新も待機も行わない。

記録は直近1回、工程数は固定上限と切捨て件数で限定する。実行中のCPU時間は
他スレッドから推計せず未取得、終端で実行スレッド自身が確定する。
原入力・銘柄・本文・鍵・例外の文章は含めない。取得、分析、保存の内容と順序、
900秒の合流上限、45秒の公開読取上限、定期実行の時刻は変更しない。
新しい監視、ジョブ、外部要求、AI生成は追加しない。

この診断の配信や後続の成功だけで、以前の時間切れの根因を修復済みにしない。
本番版・起動・実行期間を照合し、実行側の工程内訳と合流側の待機を分ける。
別の入力・別の起動の計測を、失敗した回の内訳へ流用しない。

収集確認では、ワーカーの終了と入力準備の成功を区別する。
終了結果の `jpMarketEngineInputWarm` に `error` がある場合は、
`market_inputs_unavailable` で確認を不合格にし、元の非公開の結果を保持する。
既存の収集失敗・全配信元失敗の判定を優先し、一部配信元の失敗と
旧応答での項目欠落の扱いは維持する。再試行・期限延長・追加読取は行わない。
この判定の修復を、以前の900秒の処理内訳や遅延根因の証明にはしない。
