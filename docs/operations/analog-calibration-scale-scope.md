# 過去検証の入力範囲と再利用

過去の類似局面の選択、年初時点の尺度、価格、公式営業日、材料反応、
現在の尺度に変更があれば検証を更新する。候補の原入力IDと全内容の照合を維持する。

年ごとの尺度は、その年の1月1日より前に受領した行だけを使う。
キャッシュも全対象年の尺度へ入る行を全改訂込みで結び付ける。
最新対象年の年初より後の受領変更は、それだけで過去検証を再実行しない。
現在の尺度や封印した過去局面が変われば従来どおり再実行する。

過去検証の式、閾値、評価期間、材料採用比較、現在の表示入力、保存原本は変えない。
校正キーの内部スキーマを更新し、従来の加速用キーを新しいキーとして流用しない。
保存形式は既存のものを使う。Todayの順番とFUTURE MAPの最初のチャートは変更しない。

手元の回帰確認と、本番の自然巡回での所要時間・再利用確認は別に受け入れる。

## 同じ呼出し内の時点検査

現在尺度と直近年の尺度は、同じcutoffで一度検査した状態の履歴を使う。
複数の後続経路も、同じ呼出し内で全価格履歴の時点検査を一度だけ共用する。
各候補の内容ID・方針の検証、全履歴の改訂矛盾・将来受領・欠測の判定は維持する。
次の呼出しには持ち越さず、cutoffや訂正が変われば改めて全行を検査する。
計算結果・候補選択・判断権限・保存形式は変更しない。

## 局面を組み立てる間の所有

類似局面の内部読取では、行ごとの時点・改訂・内容の検査をすべて行い、
使わない時点検査の証明書は生成しない。文字列・数値など変更不能な値だけを共用し、
入れ子の値は検査前に深いコピーを持つ。状態系列は最後の有効な観測を選んでから
受領情報をコピーする。次の呼出しへ検査結果を持ち越さない。
一般の時点検査は従来どおり、独立した行と内容ハッシュ付き証明書を返す。
欠測・将来受領・不正な改訂・同改訂の矛盾は従来の検査で判定する。

## チャートと収集後の照合

チャート側の時点検査も、変更不能な値への再帰コピー呼出しだけを省く。
入れ子の独立所有、全行の改訂・時点検査、返す証明書の内容とIDは維持する。

既存の非公開工程出力を指定した収集CLIは、終了後に既存の管理診断をGETで一回読む。
取得は収集の元の総時間枠内で最大15秒とし、失敗しても収集を再実行しない。
既存の保存先に、固定の工程・研究対象・CPU秒・RSSだけを別ファイルで保存する。
公開標準出力には保存の成否だけを加え、診断本文や所有者の記録を出さない。
新しい収集・AI・時計は起動しない。工程記録は既存のv2文脈も保持する。

診断は最新の全体研究の観測で、収集スレッドのCPU帰属を意味しない。
収集の開始・終了との時刻範囲の一致と研究窓の包含を別々に記録し、
合流待ちや別の実行の研究を同じ収集の計算として加算しない。
