# 個別説明の暗号化保存・分割互換

個別説明の履歴が単一32MiBを超えた場合、既存保存workerは同じ本人用の
非公開接続・暗号化鍵・head・chunksの下で分割形式へ移行する。
新しい保存先・収集・時計・AI生成は作らない。全件を一つのメモリへ
展開する上限を上げず、1片は最大8MiB、通常4MiBで区切る。
元の32MiBの書出し・暗号化・読込み制限は変更しない。

## 保存と復旧

- 一つのDB読取トランザクションで全要求と完了を既存検査に通す。
  1要求とその完了は同じ片に置き、原本文・UUID・digest・時刻を維持する。
  元のDBを変更しない。非公開の一時ファイルは0600で作成し、終了時に消す。
- DB読取を閉じた後、同じAES-GCM/HKDFで各片を暗号化し、既存512KiB片の
  不変保存と全バイト読戻しを使う。変更していない暗号化片を再利用する。
- 順序・全履歴hash・全件数・各片のhashと件数を含むmanifestも暗号化する。
  全片の保存確認後だけ同じheadを比較更新し、manifestを認証して読戻す。
  head競合や期限失敗時に、元の正本や生成済みのローカル結果を捨てない。
- 復旧時は各片を順に一時DBへ検査復元し、最後の片まで全件数・全履歴hashが
  一致してから、本来のDBへ単一トランザクションで統合する。途中破損や
  異なる本文の同一UUIDは拒否する。新しいローカル履歴は保持する。
- 180秒の既存接続期限、最低1GiBの空き、1片8MiB、manifest512KiB、
  最大1000片とストリーム全体4GiBを別々に制限する。全体4GiBを確保・読込
  する処理はない。上限や空き不足は失敗として残し、全件保存済みとしない。
- 既存本人診断には形式・片数・容量だけを投影する。本文・銘柄・ID・鍵は出さない。

## 互換期間と撤去条件

小さい履歴は従来の形式で保存する。新しいreaderは従来形式と分割形式の
両方を読む。既存の現在鍵・旧鍵による復旧と鍵交代も維持する。
分割形式へ移行後のheadは旧readerでは読めないため、巻戻し先にも今回の
互換readerが必要。旧headと旧暗号化片は履歴に保持し、削除しない。
旧形式の読取経路の撤去は、実本番の自然保存・全件の独立復旧・原版一致と
巻戻し手順の受入後に別判断とし、日時経過だけでは外さない。

実装・合成32MiB超の全件復元・公開検査・本番自然保存・Render起動時の
実復旧を別々に受け入れる。手元の合格だけで本番受入や2GB資源受入にはしない。

## 同じ原本の二重検査を避ける

初回復旧では、全片の全記録を従来の原本・本文・時点・構成の検査に通して
一括統合する。その直後の保存準備で同じ検査を繰り返さない。
認証したmanifestのSHA-256・バイト数・件数と現在の片が完全一致した場合だけ、
同じプロセスで済んだ受入を共用する。部分一致・推定一致は使わない。
新規・変更片の全記録は従来どおり検査し、全保存候補を確認するまで書込を始めない。
SQLの要求IDも本文と照合する。新しいキャッシュ・保存先・時計は作らない。

前回の状態がVERIFIEDで、同じhead・全履歴hash・厳密な件数が結び付く場合だけ、
通常保存でその受入を共用する。それ以外と新しい起動では全復旧検査を行う。
180秒を延ばさず、未完了を成功に変更しない。既存本人診断へは共用した片数と
新しく検査した片数だけを残す。元の120秒/900秒や長期資源の根因受入とは別に扱う。
