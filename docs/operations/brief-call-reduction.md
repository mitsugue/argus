# 見立ての修正呼出しと自己再生成の削減

同じモデル・同じ分析対象を維持し、予定日時の転記とAI自身の追記による無駄を減らす。
本番配信と費用の受入は実装検査から分ける。

- 予定を説明するGPTは現在のcalendar根拠を `{event:根拠ID}` で選び、確認する理由を書く。既存の作成処理が同じ根拠の名称・日本時間・公表精度を付ける。
- 知らないID、前回だけの根拠、未検証の予定、参照していない根拠、壊れた記法は却下する。展開後も従来の出典・数値・断定・長さ・表示計画検査を通す。数値を削除して通さない。修正は従来どおり最大1回。
- 市場の現在位置のAI見立ては追記専用記憶と画面に保持し、次の生成では過去の解釈として読む。外部材料の本文・時刻・鮮度・根拠ハッシュには含めない。
- 新しい外部ニュース、訂正、実測反応、織り込み、予定変更、鮮度・時点の境界は入力比較に残す。既存の緊急更新、生成間隔、保存版全体の再利用、計算との同時点対応を維持する。公開GETはAIを呼ばない。

## 費用の受入

既存の使用受領台帳と見立ての `aiDiagnostics.attempts`、`callReduction`、`promptFactReuse` を使う。追加のGPT生成、価格取得、別の収集・保存基盤は作らない。

配信前後を同じ長さ・曜日・市場/イベント条件で比較する。入力・出力・キャッシュトークン、モデル別呼出し数と推定USD、修正回数と却下理由、必要な更新の到着と時点再現を別に確認する。未生成、欠測、少数、条件が異なる期間は保留。保存された成功版だけから全生成の却下率を算出しない。

最初の通常生成で新しい診断と日時表示を読み戻す。少なくとも配信後の1週間を記録して同条件の既存期間と比較する。月次請求は10月終了後に本人の請求額と照合する。送信バイト減少、合成検査の呼出し数、SDKの推定費用を請求額の削減率へ置き換えない。

## 長時間観測との分離

既存の72時間観測が予定終了または実際に中断した証跡を保存するまで、この候補による本番更新は行わない。裏の実装・検査・PRは可能。観測終了時刻の経過だけで完走や正式な資源受入としない。変更後の新しい観測時計を勝手に開始しない。
