# 前回材料の完全保持

現在と前回の材料が約49KBずつある場合、完全に同じ根拠だけの参照化では
65,536バイトの格納上限へ収まらない。現在の材料、訂正・反対材料、出典、
受領時刻、前回の説明は削らず、前回材料だけを既存の同じ文脈内へ可逆圧縮する。
別の保存先・取得経路・生成時計は追加しない。

既存の非圧縮形式と完全一致参照の形式は、そのまま読める。新形式は復元後の
全材料のハッシュ・元のバイト数・JSON構造を検証する。展開は65,537バイトで
打ち切り、65,536バイトを超える前回材料、末尾の追加データ、途中切れ、
不正な参照・ハッシュを拒否する。最終的な格納文脈の上限も65,536バイトを維持する。
現在の材料だけで上限を超える場合や、圧縮後も収まらない場合は保留する。

AIへ渡す前に前回材料を完全復元する。元から全内容が一致する根拠だけは
従来どおり一度だけ渡し、変更された根拠は全文を保持する。入力の選択、モデル、
出力上限、訂正回数は変えない。格納量の削減をトークンや請求額の削減とは扱わない。

新しい文脈のIDと選択台帳は新内容に結び付ける。過去の原版、ID、受領・完了時刻、
回答は再署名・上書きしない。保存と空の別DBへの復元を元の全内容で照合する。
本番の通常作成・保存・実表示の受入は、手元検査や配信受入と分けて確認する。
