# 金融受領範囲の原本読取

金融受領の整合性確認で、同じ原本が複数の受領版に結び付くとき、同一のSQLite読取中だけ原本のバイト列を共用する。呼出しの外へ持ち越さず、原本16件・本文合計1MiBを上限とする。単体で1MiBを超す原本は共用せず、従来の読取を続ける。上限に達すれば古い参照から外す。

受領本文のハッシュ、原本のハッシュと応答参照、利用時点、構成・範囲・複合原本の検査は変えない。未検証の内容に共用印を付けず、同じ読取スナップショットの既検証バイト列でも各受領との結合を検査する。SQLiteの読取接続と外側の受領カーソルが保つスナップショット内だけで使い、次の呼出しでは新しく読む。原本・DB・受領時刻は書き換えない。

これは重複した原本I/Oの修復である。隔離した実保存の出力一致やSQL回数の減少を、本番の時間短縮・過去の時間切れとの同一入力一致・正式資源受入へ広げない。実経路の既存検証時間とCPU内訳で別に確認する。取得・AI・タイマー・保存先・売買権限は追加しない。
