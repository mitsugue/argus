# 13Mからの画面復帰の余白

既存の `pageshow` では安全余白を同期で一回だけ測定していた。WebKitの履歴復帰で
レイアウト確定が後になる場合、その一回の値がフッターに残る。復帰時は直ちに
測り、二つの描画フレーム後にも同じ上限34pxで測る。表示復帰・フォーカスも
同じ処理へ接続し、重複予約と破棄後の予約を取り消す。取得・AI・保存は始めない。

`web/scripts/return-geometry.test.mjs` は同期測定0px→レイアウト確定34px、重複、
解除を確認する。手元390px幅の別ページ往復で下端844px・上端792pxが一致した。
iPhoneの本人環境で指摘された事象そのものの根因・解消の受入とは分ける。
現行の余白上限・タップ44px・既存画面保存・認証は変えない。配布版更新は別工程。

公開検査の最初の候補be37add9は二つの再生で86px高さ/40px下端余白が失敗した。
検査は34pxのCSS入力と測定を別ブラウザタスクで行っており、その間に本番の
遅延再測定がChromiumの実値0pxへ戻していた。入力と測定を同じタスクで行う
ように修正し、86px・40px・44pxの既存基準を維持する。最初の失敗を保全する。
