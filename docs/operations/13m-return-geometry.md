# 13Mからの画面復帰の余白

既存の `pageshow` では安全余白を同期で一回だけ測定していた。WebKitの履歴復帰で
レイアウト確定が後になる場合、その一回の値がフッターに残る。復帰時は直ちに
測り、二つの描画フレーム後にも同じ上限34pxで測る。表示復帰・フォーカスも
同じ処理へ接続し、重複予約と破棄後の予約を取り消す。取得・AI・保存は始めない。

`web/scripts/return-geometry.test.mjs` は同期測定0px→レイアウト確定34px、重複、
解除を確認する。手元390px幅の別ページ往復で下端844px・上端792pxが一致した。
iPhoneの本人環境で指摘された事象そのものの根因・解消の受入とは分ける。
現行の余白上限・タップ44px・既存画面保存・認証は変えない。配布版更新は別工程。

公開検査の最初の候補be37add9は二つの再生で86px高さ/40px下端余白が失敗した。
検査は34pxのCSS入力と測定を別ブラウザタスクで行っており、その間に本番の
遅延再測定がChromiumの実値0pxへ戻していた。入力と測定を同じタスクで行う
ように修正し、86px・40px・44pxの既存基準を維持する。最初の失敗を保全する。

## ARGUS内の13M入口（2026-10-10追加候補）

外部サイトへのリンクはホーム画面版ARGUSの範囲から外れ、iPhoneのブラウザ欄を
表示する。入口をARGUS自身の `#13m` に変更し、共通ヘッダーとフッターを保持した
まま既存13Mの `/embedded/` 読取画面を表示する。矢印は入る前のARGUSページへ
戻す。13M側のタブは上部へ置き、フッターを二重にしない。

埋込み画面の余白・アニメーションの解除は描画前に適用する。手元390px幅では
フレーム下端792px、共通フッター上端792px/下端844pxを確認し、往復後も同じ位置。
フッター内のボタンは上端797px/下端841pxで、外枠の位置と分ける。
既存の履歴復帰の余白再測定も維持する。幅320〜430pxの既存全画面再生は別に行う。

認証や実データの内容は13M内に留める。親が受け取るのは準備完了と許可した
移動先だけで、送信元のoriginとframeのwindowの両方を確認する。不正な移動要求は
無視する。遅延時の案内は表示の状態であり、実価格や本人認証の成功判定ではない。
13Mの既存収集・保存を共有し、ARGUS側に収集や保存の並立基盤を作らない。

本番の長時間観測を中断する統合・配信は行わない。実終了または中断の証跡後に
別工程で配布版を更新する。iPhoneホーム画面版のURL欄/フッター/本人確認/実受領の
最終受入は未観測で、手元の固定データによる検査と分ける。
