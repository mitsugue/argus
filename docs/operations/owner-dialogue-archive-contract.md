# 保存した説明の検査契約

現在の生成は、分析手法・対象・期間を結び付けた比較の検査を必ず通す。
HTTP入力から過去の検査を選ぶ入口は設けない。

比較の手法・対象・期間を検査する処理は、コード履歴
`c90ec471650825071507c914d3c00a6c6ce57114` で追加された。
その導入前の所有者向け保存版には、この結び付きがない。
過去の説明を現在の手法の検証結果とみなさず、保存原文として復旧する。

復旧時に限り、現行検査が `validation_method_scope_mismatch` で拒否した場合に
旧契約の読み取りを検討する。受領と完了がともに
`2026-09-19T19:44:41Z` より前で、受領から完了の順序が正しく、
明示した新しい検査版や `validationSubject` がなく、
所有者向けの既存スキーマと4つの権限禁止を満たす場合だけが対象となる。
日時不明・導入時刻以後・結び付きが明示された入力は現在の検査を通す。

旧契約も、根拠ID・数値・種類・文字数・参照数・権限の検査を共有する。
仮定の扱い、表示構成、署名・内容ハッシュ、暗号、容量、原文一致の検査を維持する。
保存原文・時刻・識別IDを書き換えない。旧説明を新しい生成結果や
予測の追加効果として採用しない。

全件の原本復旧が完了するまで、通常の個別説明の生成を停止する条件は維持する。
互換で読めた件数だけを既存の非公開診断へ記録し、本文や銘柄は出さない。
