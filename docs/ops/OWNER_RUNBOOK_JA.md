# ARGUS オーナー運用手順書（1枚）

この 1 枚だけで、平常時の確認・切替・戻し・障害の初動ができます。
専門用語は最小限にし、実際に押す場所と読む数字だけを書いています。
最終更新 2026-09-29。

---

## 0. 毎回覚えておく 3 つ

| | 場所 | 使うとき |
|---|---|---|
| アプリ | iPhone ホーム画面の ARGUS / `https://mitsugue.github.io/argus/` | 普段の利用 |
| サーバー | Render ダッシュボード → `argus-backend` | 設定変更・ログ |
| 変更履歴 | GitHub `mitsugue/argus` の Pull requests | 何がいつ入ったか |

**アプリが変でも、まず落ち着いて 1 分待つ。** 新しい版を配信した直後の
2〜5 分は、サーバーが再起動しているため表示が欠けることがあります。

---

## 1. 生きているかを 10 秒で確かめる

ブラウザで次を開きます。ログイン不要です。

```
https://argus-backend-3j2m.onrender.com/healthz
```

- `"status":"ok"` と出れば、サーバーは動いています。
- `backendVersion` が、いま動いているアプリの版です。
- 何も出ない・エラーページ → サーバーが落ちているか再起動中。5 分待って再確認。

次に、準備完了かを見ます。

```
https://argus-backend-3j2m.onrender.com/readyz
```

- `"ready":true` なら、保存データの復元まで終わっています。
- `false` が 10 分以上続く → 私に連絡（復元が止まっています）。

---

## 2. 画面が真っ白・ログインできない

順に試してください。上から順に軽い対処です。

1. アプリを完全に閉じて開き直す（iPhone は上スワイプ）。
2. Safari で `https://mitsugue.github.io/argus/` を開く → その後アプリを開き直す。
3. 本人確認の画面が出たら、パスワードで入り直す。
   **新しい版を配信した直後は、アプリが自動更新して本人確認に戻ります。これは正常です。**
4. それでも駄目なら「4. 認証を一時的に戻す」へ。

---

## 3. 契約プラン（メモリ）を変える

Render ダッシュボード → `argus-backend` → **Settings** → Instance Type。

- 変更すると再起動します（2〜5 分、その間アプリは表示が欠けます）。
- 変更後に `/healthz` と `/readyz` を確認。
- **判断の基準**: 私が報告する「ピーク」が、契約するメモリの **7 割以下**であること。
  例：ピーク 1.6GB なら 4GB は安全、2GB は不可。

戻すときも同じ場所で戻すだけです。データは消えません。

---

## 4. 本人確認（Face ID）を一時的に戻す

アプリに入れなくなったときの最終手段です。

Render → `argus-backend` → **Environment** → `ARGUS_OWNER_AUTH_REQUIRED` を
`1` から `0` に変更して保存。再起動後、本人確認なしで入れます。

- **データは消えません。** パスキーも登録されたまま残ります。
- 戻したら私に連絡してください。原因を直してから `1` に戻します。
- **注意**: この値は `0` か `1` 以外（空欄を含む）にしないでください。
  空欄にするとサーバーが起動しなくなります。

パスワードを忘れた場合は、同じ Environment の
`ARGUS_OWNER_PASSWORD_HASH` を新しいハッシュに差し替えます（作り方は私に依頼）。

---

## 5. 「build failed」メールが来た

Render からのメールです。**アプリは止まっていません。** 新しい版の配信に
失敗しただけで、前の版がそのまま動き続けます。

1. まず `/healthz` を見る → `ok` なら緊急ではありません。
2. Render → `argus-backend` → **Deploys** → 一番上の失敗した行をクリック
   → 下にログが出ます。最後の 20〜30 行を私に送ってください。
3. よくある原因は、外部のライブラリ配布元との通信が一時的に不調になること。
   時間を置くと直ります。

## 6. 数字の読み方（私の報告に出るもの）

| 言葉 | 意味 | 目安 |
|---|---|---|
| 保存開始時 RSS | 30 分ごとの保存が始まる瞬間の常駐メモリ | 小さいほどよい |
| ピーク | 起動してから最も多くメモリを使った瞬間 | 契約の 7 割以下 |
| 常駐（inventory） | メモリに置いたままのデータ量 | 減るほど 2GB に近づく |
| tick | 30 分ごとの生成・保存処理 | 1 回 2〜4 分 |
| 受入（acceptance） | 配信後に自動で行う画面の検査 | 失敗しても配信は済んでいる |

---

## 7. 私に連絡するときに送ると早いもの

- `/healthz` と `/readyz` の表示（コピーでも写真でも可）。
- 困っている画面のスクリーンショット。
- Render のメールなら、Deploys のログ末尾 20〜30 行。

**送らなくてよいもの**: パスワード、ハッシュ、API キー、秘密ファイルの中身。
これらは私が知る必要がなく、知るべきでもありません。

---

## 8. やってはいけないこと

- `ARGUS_OWNER_AUTH_REQUIRED` を空欄にする（起動しなくなります）。
- Render の Disk（`/var/data`）を削除・縮小する（保存データが消えます）。
- `argus-backend` サービス自体を削除する（PWA の接続先です）。
- 秘密ファイルや環境変数の値をチャット・GitHub に貼る。
