# 日経平均の指数ベースEPS/PER：ARGUS代理値（2026-09-29）

## なぜ代理値か

仕様は「日経平均 = 指数EPS × 指数ベースPER」で過去局面の経路を現在の円へ翻訳することを求める。
公式値は日経平均プロフィルの日次サマリーに毎日載るが、機械の自動演算の入力に使うことは日経の区分で
**非表示利用**にあたりライセンス契約が要り、同サイトはブラウザ以外に403を返す。J-Quantsに指数のPER/EPSは
どのプランにも無い。そこで、すでに権利を持つ入力から同じ量を再構成する。

- J-Quants Standard `/equities/valuation`：個別銘柄の予想EPS・実績EPS（日次）
- J-Quants Standard `/equities/bars/daily`：個別銘柄の終値
- 日経が無料公開する**月末時点のウエート一覧CSV**（日経平均プロフィル → 指数情報 → 「ウエート一覧(CSV)」）
- 日経平均の終値（既存のYahoo ^N225 日足キャッシュ）

## 計算

日経平均は株価換算係数 f_i 付きの株価加重：`Index = Σ P_i·f_i / 除数`、ウエート `w_i = P_i·f_i / Σ P_j·f_j`。
したがって `f_i ∝ w_i / P_i` で、月末ウエートとその日の終値から係数が復元できる（多数派の1.0で尺度を固定、0.1刻みへ丸め）。
係数が分かれば除数は消える：`PER_proxy = Σ P_i·f_i / Σ EPS_i·f_i`、`指数EPS = Index / PER_proxy`。

予想EPSが赤字の銘柄を「符号付きで合算」するか「0とみなす」かは無料ページに明記がないため両方を計算し、
公式系列との実測誤差が小さい方を採用する（`recommendedVariant`）。

## 出力の約束

- `basis = ARGUS_PROXY_INDEX_BASED_PER`。公式値（`NIKKEI_225_INDEX_BASED_PER`）とは別の基準として常に表示する。
- 係数の復元・銘柄ごとの価格/EPSの有無・赤字件数・丸めの距離を `coverage` に載せる。穴のある代理値は穴があると言う。
- 同一セッションの公式値があれば誤差%を計算して同乗させる。
- D04 は公式行が LICENSE_BLOCKED のまま `officialStatus` に残り、代理値は `ARGUS_CANDIDATE` 系統で埋まる。

## オーナーの手順（1回、以後は月初に更新が望ましい）

1. ブラウザで日経平均プロフィルの「指数情報」を開き、「ウエート一覧(CSV)」を保存する（Shift_JIS、約15KB、末尾に著作権注記あり）。
2. Render の Secret Files にそのままアップロードし、環境変数 `ARGUS_NK225_WEIGHT_CSV` にそのパスを設定する。
3. 次のウォームで係数が復元され、`index-chart?index=N225&comparison=1` の `proxyValuation` に結果が出る。

このCSVは日経の著作物。**Gitに入れない・ログに出さない・第三者に渡さない。** サーバー上の私的な計算入力に限る。

## 誤差の測り方

公式の指数ベースPER（日次サマリー／ヒストリカルデータの月別表）を人が読み、代理値の履歴と突き合わせる。
2026年9月は除数が 29.83110217 で不変なので計測窓として使える。結果は本文書に追記する。

## 実測（2026-09-29、本番、ウエート表 2026-08-31）

除数の再現は 29.83110279（公式 29.83110217）で、係数の復元は正しい。
公式の指数ベースPER（日経の月次サマリー、9月分をオーナーが保存）との比較:

| 日付 | 公式 | ACTUAL_SIGNED | FORECAST_SIGNED / NON_NEGATIVE |
|---|---|---|---|
| 2026-09-18 | 21.60 | 21.09 (−2.36%) | 28.06 (+29.89%) |
| 2026-09-24 | 21.77 | 21.25 (−2.38%) | 28.27 (+29.86%) |
| 2026-09-25 | 22.05 | 21.53 (−2.37%) | 28.63 (+29.85%) |
| 2026-09-28 | 21.88 | 21.37 (−2.33%) | 28.42 (+29.90%) |

予想EPS方式が3割高いのは、J-Quantsの予想EPSが225社中22社で欠けており、その22社の株価は分子に入るのに利益が分母に入らないため（`coverage.missingForecastEpsCount`）。
誤差の日次ばらつきは0.02%ポイントと極めて小さく、外れ方は一定＝構造的な欠損であって計算のぶれではない。
実績EPS方式は−2.4%で安定しているが、公式は予想ベースなので基準が違う。

そこで schema v2 で2方式を追加した。
- `FORECAST_WITH_ACTUAL_FALLBACK`: 予想が無い社は実績EPSで代替（`coverage.actualEpsFallbackUsed`）。
- `FORECAST_COVERED_ONLY`: 予想が無い社は分子（株価）からも外す。

推奨方式は、この2方式の誤差が本番で数営業日ぶん揃ってから、`compare_with_official` の平均絶対誤差が最小のものに固定する。
それまで `recommendedVariant` は既定のままで、画面の代理値表示は「公式ではない」の但し書きを保つ。
schema v2 では保存済みの v1 履歴は捨てられ、次のwarmから再構成される（1 warm あたり 5 営業日）。

### v2 の実測（2026-09-29 05:15Z、同じ4営業日）

| 方式 | 平均誤差 | 最大 | ばらつき |
|---|---|---|---|
| FORECAST_COVERED_ONLY | +0.76% | 0.81% | 0.04pt |
| ACTUAL_SIGNED | −2.36% | 2.38% | 0.02pt |
| FORECAST_WITH_ACTUAL_FALLBACK | −9.69% | 9.70% | 0.01pt |
| FORECAST_SIGNED / NON_NEGATIVE | +29.88% | 29.90% | 0.02pt |

**推奨方式は FORECAST_COVERED_ONLY に固定**（`argus_index_valuation_proxy.RECOMMENDED_VARIANT`）。
推奨はコード上の決定であり、保存状態から復元しない。残る +0.8% は、予想の無い22社について日経が自社予想を使っているのに対し、代理値はその22社を両辺から外していることによる系統差。
公式値が改めて読める日が来たら `compare_with_official` で再評価し、定数を更新する。

## D04（EPS基準・バリュエーション）の点灯規則（2026-09-29 オーナー決定）

原典は「日経平均の理論値 = EPS × 17/18/19/20/21倍のラダー」を定義しているが、点灯する倍率は定めていない。
オーナーが「決めていない・提案でよい」としたため、ARGUS候補規則として **指数ベースPERが 19倍（高評価帯）以上で点灯** する（`jp_market_engine.D04_ACTIVATION_RULE`、系統 ARGUS_CANDIDATE）。
ラダーは参考水準であり支持線・抵抗線ではない。公式値が読める日は公式のPER、読めない日は代理値（FORECAST_COVERED_ONLY）で判定する。

## 月初のウエートCSV差し替え（オーナー操作）

1. 日経の「日経平均株価 構成銘柄ウエート」の月末CSV（Shift_JIS）を取得する（配信URLは `scanner.py` の `_NK225_WEIGHT_*` 付近と本書冒頭を参照）。
2. Render → 本番サービス `argus-backend-3j2m` → Environment → Secret Files で `nikkei_stock_average_weight_jp.csv` を開き、Contents を新しいCSVの中身で置き換えて保存する（ファイル名は変えない）。
3. 保存で自動再デプロイが走り、直後の warm で係数が再導出される（`proxyValuation.weightsAsOf` が新しい月末日になる）。
4. 古いままでも動作は続くが、構成銘柄の入替・株式分割があると誤差が広がるため、毎月初に更新するのが望ましい。

## 過去への時点再構成（2026-10-02、実装・テスト済、本番未接続）

現行の履歴は、保有するウエート表の基準日以降の営業日だけを最大60件保持する（`_JP_INDEX_PROXY_HISTORY_LIMIT`、
`_jp_index_proxy_warm` の `day >= table["asOf"]`）。入手時刻も計算時刻なので、過去の基準日からは見えない。
`argus_index_valuation_backfill.py` は同じ式（`proxy_valuation`）で過去の各日を再構成する純関数で、通信・時計・保存を持たない。

- 係数：その日に有効な係数集合だけを使う。月末ウエート表（基準日から40日以内）か、そこから
  宣言済みの係数イベント（入替・係数変更・分割）を逆にたどった集合。イベント表の不整合は拒否する。
- 予想EPS：その日より**前**に開示された決算短信だけ。年次決算が未開示の最も古い会計年度の最新予想を使う。
  開示後の株式分割はJ-Quantsの調整係数でその日の株数単位へ換算する（換算有無を件数で記録）。
- 各点に方式・基準・予想のある株価加重比率（`forecastPriceShare`、0.80未満は使用不可）・係数の出所と経過日数を載せ、
  入手時刻は観測日の翌暦日 00:00Z（`RECONSTRUCTED_SCHEDULED_PUBLICATION`、`historicalVintageVerified: False`）。

**律速は係数（ウエート）の過去分。** 予想EPSと終値はJ-Quants Standardで過去にさかのぼれるが、
ウエート表は現在の月末1枚しか持っていない。10年の同一定義履歴には、各月末のウエート表か、
基準表から過去へ戻すための係数イベント一覧（効力日・コード・変更前後の係数）が必要。どちらも製品リポジトリには入れない。
