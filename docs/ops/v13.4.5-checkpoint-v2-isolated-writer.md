# ARGUS v13.4.5 Checkpoint V2 isolated writer

## Scope and production state

This release candidate changes only the Checkpoint V2 Stage 1 writer
topology. It does not enable Stage 1, change restore authority, arm Formal
Soak, or alter Remote Journal behavior. Production remains `legacy_only` and
V2 restore authority remains false until a separate owner-approved rollout.

## Audited old data flow

The ordinary mission window calls `_osint_persist_locked`. The parent reads the
WAL maximum sequence, builds the bounded legacy checkpoint mapping, seals it,
writes and read-backs the authoritative legacy JSON, and applies the existing
verified WAL compaction policy. When Stage 1 was enabled, the same long-lived
parent then called `argus_checkpoint_v2.write_generation` directly.

That direct call allocated or retained these generation-sized values in the
backend process:

| allocation | creator/owner | approximate production size | lifetime | isolated parent allocation |
|---|---|---:|---|---|
| legacy checkpoint mapping and sealed shallow owner | `scanner._osint_persist_locked` | 100–200 MiB logical state | through legacy persistence | required for legacy; released before child launch |
| per-section canonical stream/hash traversal | `argus_checkpoint_v2.write_generation` | section dependent, up to 120 MiB | each section | avoided |
| bounded row byte buffers | `_encode_bounded` | up to 8 MiB per row | SQLite insertion | avoided |
| SQLite page cache/transaction state | `sqlite3` writer | generation dependent | generation transaction | avoided |
| generation manifest and section table | V2 writer | bounded below 1 MiB | promotion | parent reads only this bounded metadata |
| full V2 read-back object graph | `restore_generation` | generation-sized | validation | avoided; child performs it |

The failure mode was allocator and mapping retention in the long-lived process:
the OS could not reclaim the child-independent address space at the end of a
generation, and production RSS ratcheted despite object release.

## New boundary

The parent writes an integrity-sealed descriptor below the persistent V2 root
and launches `python -m argus_checkpoint_v2_isolated --job <descriptor>` using
a new interpreter and process group for every generation. The descriptor is
limited to 64 KiB and contains build/boot/window identities, the verified
legacy file hash and size, WAL lower/upper sequence, a pinned generation ID,
deadline, and schema metadata. It never contains checkpoint sections, symbols,
portfolio data, credentials, or raw bytes. All derived paths are canonicalized
and confined to the configured Persistent Disk root.

The child:

1. verifies the descriptor envelope and deadline;
2. verifies the source file identity/hash/size, WAL availability, and exact
   equality between the descriptor boundary and sealed checkpoint cursor;
3. loads the sealed legacy checkpoint itself;
4. builds the candidate SQLite generation in a job-local directory;
5. fsyncs, hashes, and fully restores the candidate to verify all rows;
6. writes an integrity-sealed result no larger than 64 KiB;
7. exits.

The child cannot write the active production manifest. The parent accepts only
an exit-zero result matching its job, build, boot, mission window, source, WAL,
and generation identities. It rechecks the immutable source, database hash,
candidate-manifest hash, and SQLite integrity before atomically moving the
generation and promoting the small active manifest. Promotion is idempotent.
Legacy remains the sole restore authority.

### Exact WAL boundary contract

All sequence fields are JSON non-negative integers. Missing, null, boolean,
string-coerced, or negative values are invalid. Zero is an exact genesis value;
it is never a wildcard and never means unknown.

| field | authority | interval semantics | valid zero | comparison |
|---|---|---|---|---|
| checkpoint included WAL sequence | verified legacy receipt and sealed `missionTickDurability.walAppliedSequence` | inclusive snapshot coverage/target | yes, only for exact genesis | both must equal descriptor target |
| WAL lower sequence | verified checkpoint `walCompaction.compactedThrough` | inclusive coverage already compacted; live target records begin at lower + 1 | yes | must be at or below target |
| WAL upper / descriptor target | parent-pinned included sequence | inclusive generation target | yes | exact equality only |
| active WAL applied sequence | sealed checkpoint durability state | inclusive source cursor | yes | exact equality with target |
| verified remote WAL sequence | verified Remote Journal receipt | independent remote durability/compaction evidence | yes | may not be substituted for target |
| child reconstructed sequence | complete, ordered, hash-valid live interval plus compacted lower coverage | inclusive reconstructed target | yes | must equal descriptor target |
| parent promotion sequence | child result rechecked against the parent descriptor | inclusive promoted target | yes | must equal child and descriptor |

The child requires every live sequence in `(lower, target]`, verifies framing,
record hashes, uniqueness, file order, and the retained hash chain. A fully
compacted `lower == target` checkpoint may have no target records. Production
compaction may leave exactly one `checkpoint_verified` receipt at `target + 1`;
that receipt must chain from target and name the same compacted lower boundary.
No other post-target record is accepted.

| case | result |
|---|---|
| checkpoint includes 0 and no WAL exists | valid exact genesis |
| checkpoint includes N and lower equals N with no later WAL | valid fully covered checkpoint |
| checkpoint includes N but live WAL extends through M | invalid for direct generation; a newly verified/replayed source must explicitly include M before target M is eligible |
| descriptor M, child reconstructs M | eligible for bounded parent promotion |
| descriptor M, child reconstructs M-1 | `WAL_boundary_invalid` |
| descriptor M, child reconstructs M+1 | `WAL_boundary_invalid`, except the one verified compaction receipt described above |
| nonzero source with probe target 0 | `WAL_boundary_invalid`; zero is not inferred or widened |
| stale descriptor after source or WAL advances | fail closed before promotion |

The original closure probe loaded a real public checkpoint with a nonzero
source cursor but overwrote the synthetic receipt, WAL lower/upper, and
descriptor target with zero. The exact equality rejection therefore proved the
production guard and exposed a fixture defect. The corrected probe constructs
each cycle's fixture in a separate short-lived process: it writes real
deterministic WAL records, applies the production compactor, seals a matching
production-shaped source, exits, and then lets the independently spawned writer
child read those immutable files. Targets advance by 17 for every cycle and are
nonzero in all 32 cycles. The long-lived measurement parent never loads the
generation-sized source mapping.

There is no production in-process fallback. `write_generation` remains a
low-level unit/migration primitive, but the Stage 1 production path contains no
call to it. A child failure is recorded through `record_failure`, clears any
arm, keeps `authorityPromotionBlocked=true`, and waits for a later qualified
window.

## Lifecycle and recovery

The parent holds `checkpoint-v2.writer.lock` across descriptor creation, child
execution, verification, and promotion, so a second mission is rejected. The
child has its own candidate-root transactional lock. Linux children request a
parent-death signal. Timeout handling sends SIGTERM to the child process group,
waits a bounded five-second grace, sends SIGKILL if required, and always calls
`communicate` to reap the process.

Job directories are strictly shaped, bounded to sixteen, and reconciled under
the global lock before a later job. Active manifests are never changed by a
failed child, invalid result, stale source, lock collision, or timeout. A
candidate from a different boot/build/window is not eligible for promotion.
No reconciliation path arms or starts Formal Soak.

Safe public telemetry reports `writerMode=isolated_process`, bounded job state,
generation ID, parent RSS/PSS/FD/thread before and after, child peak/duration/
exit classification, per-generation sampled cgroup peak, separate lifetime
cgroup peak, disk free, and retained/pending counts. It does not expose
filesystem paths or checkpoint contents.

## Acceptance and resource gate

The automated long-lived-parent test performs 32 consecutive generations with
one unchanged parent and 32 fresh child processes. It requires 32/32 verified,
distinct child PIDs, pending zero after each cycle, retained generations at or
below four, free disk at or above 1 GiB, and cycles 3–32 parent RSS-after spread
at or below 128 MiB. The Linux production-shaped resource probe remains the
authority for the exact 4 GiB cgroup, 127–160 MiB generation, and total cgroup
peak below 3 GiB; a deployment must not proceed if that gate is unavailable or
fails.

Failure tests cover source/descriptors/results, source identity, lock collision,
SIGTERM/SIGKILL, SQLite transaction failures, timeout, stale/orphan cleanup,
and no false manifest promotion. The existing v13.4.4 Formal Soak truth table
continues to fail closed for disabled, unarmed, rejected-resource, blocked-
authority, non-natural, and incomplete Stage 1 states.

## Finite owner-approved rollout plan (not executed by this PR)

1. Merge the isolated-writer release.
2. Allow normal Render Auto-Deploy while Stage 1 stays disabled.
3. Verify exact backend/manifest SHA and boot identity.
4. Observe two ordinary legacy-only natural windows.
5. Obtain explicit owner approval to enable Stage 1.
6. Apply the one expected configuration restart.
7. Verify `writerMode=isolated_process` and legacy restore authority.
8. Observe at least eight distinct natural V2 windows.
9. Prove the parent post-generation memory plateau and total peak gates.
10. Perform the separately approved isolated V2 restore proof.
11. Evaluate V2 authority promotion under the existing owner contract.
12. Do not arm/start Formal Soak until every acceptance gate passes.

Rollback is finite and non-destructive: disable Stage 1, keep legacy authority,
preserve all retained V2 generations and incident evidence, and perform no data
deletion.
