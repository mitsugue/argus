# 日本株分析エンジンの製品要件

2026-09-09。総称は「日本株分析エンジン」、コード上の総称は `jp_market_engine`。
人名に由来する名称・識別子を製品全体で使用しない。表示だけの変更ではない。
各機能には需給分析、類似相場分析、価格シナリオ、反転分析など役割を表す名称を使う。
改名と分析ロジックの改善は別の変更として検証する。

## 適用範囲

画面、API、コード・パス、設定、プロンプト、保存データ、キャッシュ、配布物、
テスト、コメント、説明資料、現行の変更履歴まで適用する。英単語の偶然の部分一致や、
独立した商品コード・一般用語は置換対象にしない。
旧形式の互換対応が残る間は完全除去と報告しない。

原典は製品外の研究保管庫で管理し、製品には匿名の参照ID、内容ハッシュ、
観測時刻、公表時刻、入手時刻、手法の成立・撤回条件を渡す。
AIは方法と観測根拠を説明し、人名を判断の権威として使わない。
研究資料の本文・URL・チャンネル名を無審査で検索インデックスやプロンプトへ取り込まない。
既存AI回答と通知も保存データとして移行・確認する。

## 追加理論の検証候補

ここでの「仕様追加」は実装や有効性確認を意味しない。各候補は独立に
仕様、実装、実データ接続、有効性検証の証跡を持つ。

| 候補 | 必要な観測・区別 | 現在の扱い |
|---|---|---|
| 信用評価損益率 | 水準、週次変化、信用買残・売残の変化を別々に保存。公表時刻と対象週を区別。代理計算は公式値と区別 | 仕様追加。D01には評価損益率の入力・計算処理が一部実装済み。実データ接続と有効性は未確認。信用残の接続だけで評価損益率を接続済みとはしない |
| 個別株の貸借制約 | 貸株注意喚起、申込制限・停止、逆日歩の発効・終了時刻、対象銘柄、対象市場、単位・日数。欠測を制約なしとしない | 仕様追加。既存の日証金残高と各規制履歴の網羅性は別途検証 |
| VIXのMACDとメジャーSQ接近 | VIXの確定足・市場時刻、MACDパラメータ、交差の方向、公式SQ日までの営業日数。組合せと単独条件を比較 | 仕様追加。既存MACD処理の存在を組合せ条件の有効性とみなさない |
| 原典の予測チャート再現 | 原典で観測できる軸・基準日・期間・描画条件と、ARGUSの計算済み価格シナリオを別の成果物として記録。未公開計算式を推定で再現済みとしない | 仕様追加。画像の類似だけでは数値再現・予測精度を証明しない |
| 信用期日 | 制度信用と一般信用を区別。制度・契約・建日・休日処理に従う。一般信用に一律の期日を当てはめない。約定単位の必要情報がない場合は不明 | 仕様追加。信用残の増加日から個別建玉の期日を確定しない |

候補は検証前にBUYや予測確率へ直結させない。検証は公表時刻を守った時点再現、
学習期間と固定検証期間の分離、基準モデルとの比較、欠測・費用・適用市場の記録を要する。
日本株指数・個別株・米国株の根拠を混ぜず、類似度とその後の整合性を分ける。
公式の指数EPSとETF・銘柄集計からの代理値も区別する。

## 移行と受入条件

1. 元データ、保有銘柄、設定、予測履歴、検証結果を保全し、件数と内容ハッシュを記録する。
2. APIの生成側・利用側、保存形式、定期処理、ハッシュで結ばれた根拠IDを依存順に更新する。
   文字列が変わる成果物は新IDを持つ。過去の署名を新内容へ流用しない。
3. 履歴の旧原本は製品外に保全する。新形式への変換では数値・判断・観測時刻を照合し、
   元原本のハッシュと新IDの対応を製品外の移行台帳で追跡する。
4. 互換対応には開始日・撤去条件を付ける。稼働中の旧クライアント・定期処理と保存データの
   移行確認が終わる前に旧読み取り経路を削除してデータを失わない。
5. Today、個別株、ニュース・イベント、Settings、詳細説明、AI回答を本番ブラウザで確認し、
   API、配布JS・ソースマップ・Service Worker、更新後のキャッシュも照合する。
6. 禁止対象の具体的な検査設定・旧形式の対応表は製品外で管理する。製品には汎用検査器と
   匿名のルールIDだけを置く。設定未取得を検査合格にしない。

Git過去履歴、既存ログ、バックアップ、外部サービス記録は現行成果物と分けて残存を記録する。
履歴の強制書換えや記録削除は実施対象・影響を明示して別に判断する。
確認していない端末・外部領域を含む完全除去宣言は行わない。

### 端末内の履歴を読む移行経路

移行期間は新形式を含む本番版の初回配信から、利用者のiPhoneホーム画面版の
判断履歴・保有銘柄・設定を確認し、サーバー保存データと接続する定期処理の
移行確認がそろうまでとする。初回配信日は配信時に台帳へ記録する。
確認後の次の変更で旧形式の読取り経路を撤去し、バックアップの再取込みは
製品外の移行ツールを経由させる。未使用端末を推測で移行済みにしない。

端末内の判断履歴は元の内容IDを検証してから変換し、件数・判断・時刻を維持する。
変換前後のダイジェストとID対応を端末内に記録し、保存容量不足・破損時には
元の履歴を消さない。変換した過去の記録に現在の売買判断の権限を付けない。
更新時のキャッシュ回復は取得済みの表示データだけを対象とし、チャートに
利用者が描いた線・保有銘柄・設定・判断履歴を削除しない。
